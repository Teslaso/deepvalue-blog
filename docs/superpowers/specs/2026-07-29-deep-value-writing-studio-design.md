# Deep Value 写作台设计

日期：2026-07-29  
项目：`deepvalue-blog`  
状态：已确认

## 1. 背景

Deep Value 已经具备一套安全的 Obsidian 发布转换器。它以独立 Vault
中的 Markdown 为来源，支持 Obsidian 双链与图片转换，在隔离目录构建
Astro 站点，并在用户确认后精确提交和推送发布文件。

现有流程解决了“如何安全发布”，但没有解决“如何在接近最终博客效果的
环境中写作”。日常写作仍需要在 Obsidian、终端命令、发布确认页和博客
预览之间切换。

本设计新增一个本机 Web 工具“Deep Value 写作台”，把文件选择、Markdown
写作、元数据管理、图片插入、博客样式预览和现有发布流程连接起来。

## 2. 产品目标

第一版需要实现：

- 以 Obsidian Vault 内的 Markdown 文件为唯一原稿；
- 在本机浏览器中提供专注的 Markdown 编辑体验；
- 在右侧实时呈现接近博客文章页的阅读效果；
- 通过表单管理发布 frontmatter，减少手写 YAML；
- 支持粘贴、拖拽和选择图片；
- 复用现有 Publisher 的验证、隔离构建、精确提交和推送；
- 保留发布前最终确认，防止误发布；
- 检测 Obsidian 或其他程序造成的外部文件冲突；
- 不扫描、不展示、不暴露整个 Vault。

## 3. 非目标

第一版不做：

- 公网访问或云端托管；
- 手机从外部网络连接本机 Vault；
- 浏览整个 Obsidian Vault；
- 多人协作和实时协同编辑；
- AI 改写、AI 摘要或 AI 写作助手；
- 云同步、独立版本历史或复杂知识图谱；
- 全文研究数据库；
- Electron 或 Tauri 桌面安装包；
- 替换现有 Astro、Git 或 Publisher 架构。

这些能力不得阻塞第一版。以后若需要 AI 能力，应作为独立侧栏接入，
不改变 Markdown 文件的唯一原稿地位。

## 4. 已确认的产品决策

### 4.1 唯一原稿

Obsidian Vault 内的 `.md` 文件是唯一原稿。网页编辑器直接读取和保存
这些文件，不在博客仓库或浏览器存储中维护第二份正文。

### 4.2 使用范围

第一版是本机 Web 应用：

- 只监听 `127.0.0.1`；
- 可在本机 Chrome、Safari 等现代浏览器中使用；
- 不开放局域网和公网访问；
- 不把私人笔记上传到外部服务。

### 4.3 文件范围

配置中新增一个或多个明确的发布工作目录。左侧文件栏只显示这些目录内
的 Markdown。默认不扫描整个 Vault。

可以保留“打开其他文件”的未来扩展点，但第一版不实现任意路径打开。

### 4.4 发布流程

发布是两阶段操作：

1. “准备发布”：强制保存、验证、转换、隔离构建并展示真实目标页面；
2. “确认并发布”：精确应用目标文件、构建、提交并推送。

用户也可以选择“仅本地提交”或“取消”。不提供跳过最终确认的普通界面
操作。

### 4.5 预览

提供两级预览：

- 即时博客样式预览：随输入更新，用于流畅写作；
- 真实 Astro 预览：按需刷新，并在“准备发布”时强制生成。

即时预览必须明确标识自身，不得冒充已经构建的最终页面。

## 5. 技术方向

扩展现有本地 Publisher，而不是把编辑能力放进线上 Astro 网站，也不
新建桌面应用。

原因：

- 现有 Publisher 已有安全的回环服务器；
- 已有 Markdown 转换、验证、隔离构建和 Git 事务；
- 可以避免出现两套发布逻辑；
- 不会让生产站点意外包含本地文件写入接口；
- 第一版工程量和维护成本最低。

写作台与发布确认页可以共享服务器基础设施和设计语言，但职责分离：

- 写作台负责文件、编辑、保存和快速预览；
- Publisher 事务负责验证、最终预览、应用、提交和推送。

## 6. 信息架构

### 6.1 桌面布局

桌面端采用三栏结构。

#### 左栏：文章

- 工作区名称；
- 搜索；
- 新建文章；
- 最近编辑；
- 按状态查看：草稿、可发布、已发布、有修改、有错误；
- 按栏目查看：产业研究、交易、AI 应用；
- 文件标题、状态和最近保存时间。

左栏建议宽度为 280–320px。

#### 中栏：编辑

- 当前文件名和保存状态；
- 可折叠的发布信息面板；
- Markdown 工具栏；
- Markdown 编辑区；
- 大纲、字数和错误定位能力。

编辑区应获得足够宽度，不因预览而低于可用写作宽度。

#### 右栏：预览

- 即时博客样式预览；
- 桌面与窄屏宽度切换；
- 刷新真实 Astro 页面；
- 大纲定位；
- 准备发布后切换到真实目标路由。

### 6.2 顶部操作区

- 品牌与当前文档路径；
- 保存状态；
- 保存；
- 准备发布；
- 发布事务存在时显示最终确认入口。

“确认并发布”不得在尚未通过准备阶段时出现。

### 6.3 底部状态区

- 当前文件路径；
- 字数；
- 最后保存时间；
- 即时预览或真实预览状态；
- 验证错误数量；
- 构建、Git 和推送状态。

### 6.4 窄屏

小于 720px 时，不保留压缩后的三栏。界面改为：

- 文章；
- 编辑；
- 预览。

三个标签页共享顶部文档状态与发布入口。页面本身不得产生横向溢出。

## 7. 视觉设计

写作台沿用 Deep Value Editorial 视觉系统，但保持工具属性：

- 炭黑用于应用外壳、操作和状态环境；
- 暖纸用于编辑与阅读区域；
- 铜色只用于主操作、当前状态、错误定位和关键链接；
- 橄榄色用于次级状态和元数据；
- 中文正文、标题与预览使用宋体类编辑字体；
- Markdown 源码、文件路径、时间、标签和状态使用等宽字体；
- 使用直线、细边框和清晰网格；
- 基本不使用圆角、漂浮卡片和装饰阴影；
- 不引入博客首页的大图或宏观插画；
- 不使用无功能的古典纹样或装饰图标。

视觉原型采用：

- 顶部炭黑操作栏；
- 左侧略深纸面文件栏；
- 中间浅纸 Markdown 编辑区；
- 右侧标准暖纸博客预览；
- 折叠后的元数据面板显示栏目、类型、主题与就绪状态。

## 8. 第一版功能

### 8.1 文件管理

- 扫描配置的发布工作目录；
- 新建 Markdown；
- 打开 Markdown；
- 搜索标题、文件名和公开标签；
- 显示草稿、可发布、已发布、有修改和有错误状态。

第一版不提供重命名或删除按钮。这两项文件管理操作继续在 Finder 或
Obsidian 中完成。

### 8.2 Markdown 编辑

- 自动保存；
- 撤销与重做；
- 常用 Markdown 快捷键；
- 查找和替换；
- 当前行高亮；
- 标题大纲；
- 字数统计；
- 表格、列表、引用、代码块和脚注；
- Obsidian 双链；
- Obsidian 图片引用和标准 Markdown 图片。

不需要第一版实现富文本或所见即所得编辑。

### 8.3 发布信息表单

表单负责管理现有 Publisher 所需的 frontmatter，包括：

- `publish`
- `publish_id`
- `title`
- `domain`
- `section`
- `topic`
- `format`
- `summary`
- `source_type`
- `tags`
- `commodities`
- `companies`
- `tickers`
- `thesis`
- `confidence`

表单根据 `domain` 和 `format` 动态显示和验证字段。

`publish_id` 在首次生成后视为永久公共身份。界面默认锁定，修改时需要
明确警告，不允许因标题变化自动重写。

高级模式可以查看原始 YAML。表单与原始 YAML 修改必须通过同一个
frontmatter 解析器往返，不能用字符串拼接更新字段。

### 8.4 图片

支持：

- 从剪贴板粘贴；
- 拖拽；
- 文件选择；
- 填写替代文本；
- 自动生成不会冲突的文件名；
- 保存到配置的 Vault 附件目录；
- 在当前光标位置插入 Obsidian 图片引用；
- 在即时预览中显示；
- 发布时继续由现有转换器复制到博客媒体目录。

删除正文引用时不自动删除附件。这样可以避免删除其他笔记仍在引用的
文件。

如果附件保存成功但正文插入失败，保留附件并明确报告位置，不做推测性
清理。

### 8.5 预览

即时预览覆盖博客文章中常用的：

- 标题与元数据；
- 段落和标题层级；
- 列表；
- 表格；
- 引用与 Obsidian callout；
- 代码；
- 脚注；
- 图片；
- 内部链接。

即时预览只用于写作反馈。最终效果以真实 Astro 构建为准。

### 8.6 发布检查

准备发布前检查：

- 文件已经保存；
- 没有外部修改冲突；
- frontmatter 可解析；
- 必填字段齐全；
- `domain`、`section`、`format` 等枚举有效；
- `publish_id` 安全且不冲突；
- 双链可解析或按现有规则安全降级；
- 图片存在、大小写匹配且格式受支持；
- 不包含不允许的嵌入；
- Publisher 转换成功；
- Astro 隔离构建成功。

## 9. 数据流

### 9.1 启动

1. 用户运行写作台启动命令；
2. 服务加载本地 Publisher 配置；
3. 服务验证 Vault、发布目录和附件目录；
4. 服务生成会话令牌；
5. 服务只监听回环地址；
6. 浏览器自动打开写作台。

### 9.2 打开文档

1. 客户端请求工作目录内的文档；
2. 服务规范化并验证路径；
3. 服务读取 Markdown；
4. 服务解析 frontmatter；
5. 服务返回正文、结构化元数据、修改时间和内容指纹；
6. 客户端初始化编辑器和即时预览。

### 9.3 保存

1. 用户修改正文或元数据；
2. 客户端立即更新即时预览；
3. 停止输入约 1 秒后发起保存；
4. 服务重新读取磁盘元数据和指纹；
5. 若与打开或上次保存时一致，则原子写入；
6. 写入成功后返回新的修改时间和指纹；
7. 若不一致，则停止写入并进入冲突状态。

保存必须使用临时文件加同目录原子替换，避免进程中断产生半个 Markdown。
保存前使用修改时间和内容指纹进行冲突检测，并在最后一次检查后立即
替换。该机制防止正常的 Obsidian 并发编辑和误覆盖，但不承诺防御拥有
同一账户文件权限、且能精确抢占最后一个系统调用窗口的恶意本机进程。

### 9.4 准备发布

1. 客户端强制保存；
2. 服务完成冲突复查；
3. 服务把当前源文件交给现有 Publisher；
4. Publisher 验证、转换并生成暂存内容；
5. Publisher 在隔离目录构建 Astro；
6. 服务返回发布清单、真实目标路由和预览地址；
7. 客户端进入等待最终确认状态。

### 9.5 确认发布

1. 用户查看真实目标页面和文件清单；
2. 用户选择确认并推送、仅本地提交或取消；
3. 现有 Publisher 使用单次确认令牌执行事务；
4. 成功后返回提交编号、推送状态和线上 URL；
5. 客户端刷新文章发布状态。

## 10. 并发与冲突

网页编辑器默认自动保存，但不得覆盖 Obsidian 的外部修改。

每次保存比较：

- 上次读取的修改时间；
- 上次读取的内容指纹；
- 当前磁盘文件的修改时间和内容指纹。

发现外部修改后：

- 立即停止自动保存；
- 保留浏览器内尚未保存的版本；
- 显示“网页版本”和“磁盘版本”的差异；
- 提供“重新载入磁盘版本”“保留网页版本”和“打开对比”；
- “保留网页版本”需要明确确认；
- 冲突未解决前禁止准备发布。

第一版不做自动三方合并。

## 11. 本地安全

- 服务只监听 `127.0.0.1`；
- 每次启动生成不可预测的会话令牌；
- 修改型请求必须携带有效令牌；
- 发布确认令牌只能使用一次；
- 只允许访问配置的发布目录和附件目录；
- 路径必须规范化并解析真实物理路径；
- 拒绝 `..`、空字节、反斜杠逃逸和任意绝对路径；
- 拒绝通过软链接逃出允许目录；
- 不返回未授权 Vault 文件名或内容；
- 不在浏览器持久化完整文章正文；
- 不在日志中输出私人正文；
- 继续使用现有严格 CSP、无缓存和防嵌入响应头；
- 生产 Astro 构建不得包含写作台 API 或本地路径。

本机安全模型以防止误操作、普通并发编辑、路径错误、软链接逃逸和进程
中断为目标。它不把已经拥有同一 macOS 账户权限、并能在系统调用之间
恶意替换路径的进程视为可完全防御的对手。

## 12. 错误处理

### 12.1 文件错误

- 文件消失：保留编辑器缓冲区，提示另存或重新载入；
- 权限不足：停止保存并显示具体路径和修复建议；
- 外部冲突：进入冲突状态，禁止发布；
- frontmatter 损坏：保留原文并定位错误，不自动重写。

### 12.2 图片错误

- 文件名冲突：生成确定性的安全后缀；
- 不支持格式：写入前拒绝并说明允许格式；
- 文件过大：提示大小和建议，不静默压缩源附件；
- 插入失败：保留已保存附件并报告位置；
- 发布时图片缺失：停止发布并定位引用。

### 12.3 预览与发布错误

- 即时预览失败：不影响正文保存，显示局部错误；
- Astro 构建失败：保留编辑内容，不进入确认阶段；
- 目标文件冲突：沿用现有 Publisher 的拒绝覆盖机制；
- Git 提交失败：不推送，输出恢复步骤；
- 推送失败：保留精确本地提交，提供重试推送；
- 取消发布：清理临时事务，不改变跟踪的发布文件。

## 13. API 与模块边界

实现时应保持职责清晰，不把所有能力放入 `server.mjs` 或单个前端文件。

建议模块边界：

- workspace config：加载和验证发布工作目录；
- workspace index：扫描允许目录并计算文章状态；
- document store：安全读取、原子保存和冲突检测；
- frontmatter adapter：结构化元数据与 Markdown 往返；
- attachment store：图片验证、命名和写入；
- instant preview：前端 Markdown 渲染和博客样式映射；
- studio server：写作台页面和本地 API；
- publish bridge：调用现有 Publisher 事务；
- studio client：文件栏、编辑器、元数据、预览和状态 UI。

现有 Publisher 的验证、转换、事务、Git 和预览服务器继续作为唯一发布
实现，不复制到写作台模块。

## 14. 测试与验收

### 14.1 单元测试

- frontmatter 表单与 Markdown 往返不丢字段；
- 未识别 frontmatter 字段被保留；
- `publish_id` 不因标题变化自动改变；
- 文章和日志的动态必填项；
- 路径规范化与允许目录判断；
- 软链接逃逸；
- 原子写入；
- 修改时间与内容指纹冲突；
- 图片类型、文件名和重名处理；
- 即时预览的主要 Markdown 结构。

### 14.2 集成测试

- 扫描发布工作目录；
- 新建、打开和保存；
- Obsidian 外部修改冲突；
- 图片写入和正文引用；
- 保存后准备发布；
- 验证失败不会创建发布事务；
- 准备发布后显示真实路由和清单；
- 确认并推送、仅提交和取消；
- 构建失败、提交失败和推送失败恢复。

### 14.3 回归测试

- 现有 Publisher 测试全部通过；
- 现有站点测试和构建全部通过；
- CLI `publish:current` 和 `publish:pending` 行为不变；
- CLI 用户不需要使用写作台。

### 14.4 浏览器验收

- 桌面三栏布局清楚；
- 390px 窄屏使用标签页；
- 页面无横向溢出；
- 表单、编辑器和发布流程可以仅用键盘完成；
- 所有交互控件有可见焦点；
- 状态更新使用可访问的 live region；
- 颜色不是错误、成功或发布状态的唯一表达方式；
- 即时预览明确标识；
- 真实预览与目标博客关键结构一致。

## 15. 日常使用流程

1. 启动 Deep Value 写作台；
2. 从左侧打开文章或新建文章；
3. 选择栏目和文章类型；
4. 填写发布信息；
5. 编写 Markdown；
6. 粘贴或拖入图片；
7. 观察即时博客预览；
8. 点击准备发布；
9. 修复检查问题；
10. 查看真实 Astro 页面和文件清单；
11. 确认并发布；
12. 获得线上 URL、提交编号和推送状态。

## 16. 成功标准

第一版成功需要满足：

- 用户不进入终端也能完成一次正常写作和发布；
- Obsidian 与写作台始终使用同一原稿；
- 正常写作时即时预览无明显输入延迟；
- 外部修改不会被静默覆盖；
- 发布前一定看到真实目标页面与文件清单；
- 写作台不降低现有 Publisher 的安全性；
- 不打开整个 Vault 的可见或可访问范围；
- 博客、CLI Publisher 和写作台可以独立演进。
